# 明确音乐指令在 Mac 直接执行

用户授权实测并优化 ASR 文字到 Mac 后的执行路径：普通点歌直接执行，成功后不思考、
不播报“我想一想”或成功提示；复杂请求沿用 Harness。原生唤醒和云端 ASR 不改动。

将保守的音乐指令解析抽为纯函数，桥接收到文字后、任何等待提示和 Agent 调用之前分流。
本地播放用已有脚本函数在线程执行，保持 asyncio 收音/RPC 循环可响应。
音箱原生回复的中断及 AIVS/PNS 配套恢复仍须执行以避免回归收音失效；与本地点歌并行，
让实际打开音乐不必等待三秒恢复延迟，完成恢复后本轮才重新允许下一次收音。

明确曲库查询使用代码生成答案并按需播报；播放失败/找不到歌曲给短提示，不自动重复
执行或转发给 Agent。含推荐、条件、复合操作等请求保留给 Harness。

用户随后明确要求常用指令也进入代码：暂停/停止/继续由固定 Swift 辅助程序操作网易云
动态控制菜单并核对播放状态，重复命令保持状态，不发送盲目的播放/暂停切换键。
用户已授予此程序辅助功能权限。下一首/上一首使用项目曲库的文件名排序，按本程序保存的
最后打开曲目推进/回退并环绕，继续用网易云打开 NCM；不切入播放器其他在线歌单。
未接入的音量、播放模式和自动播完续播不宣称已实现。

增加逐阶段耗时、路由、Agent 调用标记与本地轻量动作记录，均保存 .runtime，
不直接写 Harness 内部会话。快速操作不再生成桌面 Agent 思考轮次，文档明确此取舍。
验证无 Agent/无成功 TTS、复杂请求回退、双任务取消、失败提示、连续收音，以及真实
Mac 文字入口和用户语音入口。分别报告打开请求耗时、清理耗时，不能把文件打开当出声。

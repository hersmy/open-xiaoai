# 你好小七：唤醒时序与原声反馈

用户反馈“大爱同学”容易与“小爱同学”混淆，且偶有迟到回应、暂停需重试和静默结果难判断。
最终确认以下协议，替代此前保留“我在”和成功短音的中间方案。

- 唤醒词“你好小七”；确认原生 ASR 开麦后回应“哎”。
- 有效命令先说“收到”，播完才执行代码或提交 Agent。
- 明确音乐控制走本地代码，执行成功“已完成”；查询继续播报数据，失败说明实际错误。
- 复杂需求走现有 DeepSeek Harness Agent，播报最终回复，不额外说“已完成”。
- 无语音活动约八秒提醒；部分识别可继续等待，保留十八秒总上限；开麦失败明确提醒。
- 所有提示和答复采用小爱原音色，原生“小爱同学”继续保留。

`voice_config.py` 统一唤醒词与拼音。固定提示由音箱原生 TTS 以 save=1、play=0 一次生成，
缓存于 /data/open-xiaoai/feedback-native-v1；后续复用缓存，不调用 Mac 合成。
复制播放器为 feedback-player，防止原生恢复 killall miplayer 误杀固定提示。
动态错误和 Agent 回复继续用原生 TTS。首次生成及 ASR/动态 TTS 仍依赖在线服务。

唤醒后检查 event.log 新增 Recognize，单纯 ubus code 0 不算开麦成功。
失败配套恢复 AIVS/PNS 后重试一次。只识别到唤醒词/提示回声不算问题，最多重开麦一次，
不重复就绪回应。清理旧 PCM、重置 KWS，提示后短暂抑制自唤醒。

近期自定义唤醒后的明确暂停/继续允许在窗口刚结束时接管；恢复中排队，不取消前端恢复，
不阻塞 WebSocket RPC。没有近期自定义上下文时不全局接管原生控制。
一条 ASR 重复相同控制词只执行一次；混合相反指令不折叠。
记录接管/忽略/排队原因，不记录未知识别全文。音频、日志、模型和诊断只保存在运行目录。

验证覆盖原生固定提示白名单、只保存不自动播放、开麦先于就绪、失败不能假报就绪、
回声重开麦、上下文边界、恢复中排队、重复控制折叠、先收到再执行再完成。
43 个 Python 与 5 个 Node 测试通过。用户已完成暂停和静默两轮现场测试，确认两轮正常，
且全部为小爱原音色。桌面语音会话沿用原历史，不因唤醒词更名另建会话。
